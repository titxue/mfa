# Chrome 商店上传包 2.4.1

准备日期：2026-11-10（Asia/Shanghai）。应用源码：`5a6dd36`（PR #7），发布时将 `package.json` 版本更新为 `2.4.1`。仅更新原商店条目 `dhipejmoajhjflafhbibojfoeogbmjgf`。

## 本次更新

- 启用或更换密码时，预先验证并重新加密本次纳入操作的恢复副本，保留历史账户内容；无法解密的副本阻止操作，避免误报改密成功。
- 兼容旧版 `accounts`、明文及加密 V1 账户库的读取和写入，不强制迁移。旧格式继续支持默认 TOTP 参数和 Steam；无法保留的自定义参数在写入前明确拒绝。
- 为旧格式操作保留本机恢复检查点，改进写入失败和中断恢复；未知旧数据保留供原始恢复导出，阻止不安全覆盖或清理。
- 权限、依赖和网络端点相对 2.4.0 未增加。

## 原位升级

旧包来自 Chrome 官方扩展更新服务的实际 2.4.0 CRX，SHA-256：`f1e5d3ff73cc59af023f29e24e2c384d36d21cd4d562b364b05267d853534131`。新包使用上述已校验的生产输出。

在同一临时 profile、固定扩展目录中依次替换旧、新文件，扩展 ID 保持一致。仅清理临时 profile 的 Service Worker 缓存以使新后台脚本生效，保留扩展存储；验证完成后删除临时 profile。

- V2 明文、V2 加密各 7 个合成账户，包含 Steam、自定义 SHA512／8 位／45 秒账户；旧 `accounts`、明文 V1、加密 V1 各 6 个合成账户，5 组全部通过。
- 首次读取及解锁没有改写原持久化数据，账户名称、密钥、类型、网站和顺序完整；固定时间验证码、主题、语言和自动填充设置保留。
- 明文备份导出、账户编辑和排序通过，旧格式写入继续保留旧格式；加密场景改密后旧密码解锁失败，新密码可解锁且账户完整。
- 恢复历史逐项重新加密、未知历史密码阻断及中断恢复由本次通过的单元／组件测试覆盖。此处浏览器验证只检查加密库改密及账户保留，不代替全设备旧密码撤销验证。

## 边界

重新加密仅针对本次纳入并验证的副本；已导出的备份、其他离线设备和系统备份不会被远程修改。未知历史密码或损坏数据会阻止密码操作，不能删除恢复历史来绕过检查。浏览器同步不提供跨设备原子事务，本机读回成功不等于所有设备已同步。

旧格式不支持非默认 OTP 参数，也没有 V2 等价的并发隔离能力。多设备应更新版本、等待同步并避免同时编辑。此次隔离测试不代表真实双设备 Chrome Sync 或商店分发升级验收。
