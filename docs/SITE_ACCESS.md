# 2.1.4 按网站授权自动菜单

## 使用方式

在网页空白处或验证码输入框右键 → 本扩展 → “在此网站启用自动菜单”。
首次确认 Chrome 的权限提示后，重新聚焦输入框即可使用，以后无需反复授权。
右键 → “在此网站禁用自动菜单”会撤销该网站授权并隐藏菜单。
在 iframe 内右键，授权/禁用对象是该 iframe 的网站，不会额外授权顶层网站。
需要重新加载 2.1.4 扩展后才会出现右键入口；网页本身无法创建扩展的右键菜单。
新增 contextMenus 权限仅用于展示和处理上述右键操作。

打开普通 HTTP/HTTPS 网站，点击扩展 → 设置 → 自动填充 → 网站授权。
点击“在此网站启用自动菜单”，确认 Chrome 的授权提示。
授权仅覆盖显示的协议和主机名，不自动包含子域名；Chrome 主机权限不区分端口。
在授权列表点击“撤销”可移除授权。
页面内联菜单总开关仍控制所有已授权网站的菜单。
未授权网站可点击扩展中的账户进行填充，失败时按现有设置回退到复制。

## 商店“主机权限理由”建议

本扩展默认通过 activeTab 在用户点击扩展后临时访问当前网页以填入一次性验证码。
自动显示验证码账户菜单属于可选功能。只有用户主动点击“在此网站启用自动菜单”并授权后，
扩展才申请该网站的具体主机权限，并为已授权网站注册内容脚本。
optional_host_permissions 中的 HTTP/HTTPS 通配模式用于允许用户选择任意网站，
不会在安装时请求所有网站的访问权限，也不会为所有网站注册自动内容脚本。
用户可在扩展设置中撤销单个网站的授权。

## 验证与限制

自动测试：bun test tests/site-access.test.ts
类型检查：npm run type-check
构建：npm run build

浏览器验收步骤（需在实际安装扩展后进行）：
1. 新网站首次打开，无自动菜单；点击扩展账户仍可填充。
2. 拒绝网站授权，无自动菜单、无动态注册。
3. 接受授权，重新聚焦 OTP 输入框显示菜单；刷新后仍显示。
4. 撤销授权，已打开页面菜单隐藏；刷新后不再自动注入。
5. 在 Chrome 权限设置中撤销授权，结果应与扩展内撤销一致。
6. 重启浏览器后授权仍生效；新增/撤销一个站点不影响其他站点。
7. 跨域 iframe 不会继承顶层站点授权；受限页面继续回退至复制。

只有具备相应权限的框架才能注入。Chrome Web Store 和浏览器内部页禁止注入。
扩展最低 Chrome 版本提高至 96，以支持动态内容脚本注册及权限 Promise API。
可选权限仍可能接受审核，不能保证缩短审核时间。
