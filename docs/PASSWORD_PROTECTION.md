# 密码保护与 Chrome 同步

账户默认通过 Chrome Sync 同步，没有独立同步开关；需要在 Chrome 中登录同一账号并开启扩展数据同步。密码保护默认关闭，此时账户以明文同步。

在设置中开启密码保护，输入并确认至少 8 位的主密码。账户名称、TOTP 密钥和网站信息一起加密。每台设备需要使用同一密码解锁；解锁持续到浏览器会话结束，也可以点击“立即锁定”。关闭弹窗和后台 service worker 休眠不会锁定；浏览器重启、扩展重载会锁定。

修改密码和关闭保护都需要验证当前密码。远端改密后需要重新解锁。关闭保护会恢复明文同步。忘记密码没有恢复或绕过入口，请妥善保管密码及备份。

旧格式账户继续使用旧格式读写，不强制迁移 V2。旧格式模式的开启保护、改密和关闭保护，会先验证并转换本机保留的全部历史版本；历史密码未知或密文损坏时，在任何账户或恢复日志写入前拒绝操作。中断的改密可能已用新密码保存本机恢复副本，但同步中的账户仍使用旧密码，此时恢复历史可能需要新密码。详见 [旧格式存储兼容说明](LEGACY-STORAGE-COMPATIBILITY.md)。

加密模式默认导出加密 JSON；选择明文导出需要再次验证主密码。导入旧明文 JSON 或加密备份后，按当前保护模式存储。加密备份使用导出时的密码，之后修改主密码不会改变旧备份。

## 实现边界

- 存储按格式分流：纯旧 `accounts` 数组继续写数组；开启保护后包装为 V1 `accountVault`。已有 V1 保持 V1，关闭保护也不会降回数组。V2 使用独立同步命名空间与恢复协议，不会回退写旧格式。读取和解锁不改写、迁移或清理账户存储。未知 `sync.state`、`local.accounts` 或 `local.state` 会阻止写入并保留在原始恢复导出中。
- PBKDF2-SHA256（600000 次、16 字节随机盐）派生 AES-256-GCM 密钥，每次加密生成新的 12 字节 IV。密码不保存；会话密钥保存在仅受信任扩展上下文可访问的 `chrome.storage.session`。
- 最低 Chrome 版本为 102。旧格式模式支持已发布 2.3.9 客户端的默认 TOTP 和 Steam 顺序读写；不支持写入自定义算法、位数或周期，拒绝时不写存储。V2 格式仍要求更新所有设备；旧客户端不支持 V2。已有明文备份、离线设备的旧副本无法被即时远程删除。
- Chrome 单条同步记录上限为 8 KB，整体上限约 100 KB。超限会报告失败，不会截断数据。V2 可能保留多个同步候选；旧格式本机历史持续增长且不自动裁剪，本机配额不足也会阻止同步写入。加密和 Base64 会增加容量占用。
- 本机写入串行化。旧格式修订检查包含完整内容及恢复日志指纹，覆盖同步记录前先写入并读回验证本机恢复日志；V2 保留独立的因果版本与冲突恢复协议。Chrome Sync 没有跨设备 compare-and-swap，最终读取与写入／删除之间仍有竞态。旧格式不能提供与 V2 相同的冲突隔离，尤其无法保全从未观察到的旧客户端修改。尽量避免多台设备同时编辑。
- 旧客户端开启保护时，本机历史可能仍是明文。新客户端会进入待恢复状态，不在读取时自动清理；需显式选择加密候选并提供正确密码，验证及加密全部历史后才能继续。若历史需要未知密码则阻止操作。原始恢复导出可能包含明文密钥，请私密保存。卸载扩展或清除本机数据会丢失本机历史。
- 旧格式恢复日志与 V2 同时存在时阻止写入。存在旧格式日志时，显式 V2 迁移也会被 `legacyHistoryMigration` 阻止；仅导出不会清除日志，不应手动删除历史来绕过保护。
- 网页脚本只能请求账户摘要和验证码，后台检查实际消息来源、站点授权和锁定状态。密钥不会发送到网页脚本。

## 验证

运行 `bun test tests`、`bun run type-check` 和 `bun run build`。

真实双设备验收：两台 Chrome 登录同一测试账号并开启扩展同步，使用测试账户验证添加、修改、删除、排序；在一端启用保护、改密、关闭保护并观察另一端；再让一端离线编辑、另一端修改，恢复联网验证冲突提示与最终记录。不要使用真实账户密钥做自动化测试。
