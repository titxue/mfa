# 恢复副本与密码轮换

本文说明密码轮换的修复设计、安全边界与验收要求。验证矩阵是待执行的检查清单，不代表测试已通过。

## 问题与目标

此前 `sealJournal` 只加密明文记录，直接保留已经加密的恢复副本。因此，即使当前账户已改用新密码，本机恢复日志仍可能保留旧密码可解密的相同 MFA 密钥。

修复目标：启用或修改密码成功后，本次读取并纳入事务的当前账户及恢复历史均由目标密码保护，账户内容不丢失。不能仅检查当前记录是否拒绝旧密码，还必须逐项检查本机恢复日志及已知同步候选。

## 写入前预检

- 收集当前记录、本机恢复日志中的 `current`、`pending`、`conflicts`、`legacy`，以及已读取的同步候选和旧格式来源。保留历史账户内容，不自动删除恢复版本来绕过错误。
- 每份加密历史都按自身的盐值派生密钥并验证解密，不能把当前会话密钥直接用于不同盐值的历史。明文历史也纳入重新加密。
- `change` 先验证当前密码，再尝试使用当前密码和目标密码解密历史。允许两种密码，是为了处理此前失败并回滚后混合的旧、新密码历史；不代表支持任意第三种历史密码。
- `enable` 只能使用本次填写的目标密码解密加密历史。若历史仍由原密码保护，可以先用原密码重新启用保护，再使用 `change` 改为目标密码。原密码必须能解开全部相关加密历史，损坏的历史不能靠这一步修复。
- 生成目标密码的新盐值和密钥，对历史重新加密并验证。所有解密和重新加密准备完成之前，不写账户、同步记录、恢复日志或会话。

若任何格式有效的历史密文不能用上述密码解开，抛出 `recoveryPasswordRequired`：

> 有些恢复副本使用其他密码或已损坏，本次未修改密码或数据

这一提示仅适用于写入前预检失败，不适用于提交已经开始后的存储失败。结构无效的日志或同步数据仍由既有校验阻止写入。错误消息提供全部 12 种项目语言，未知语言回退到英文。

不要建议删除历史来继续操作。导出恢复副本只会复制现有内容，不会清除或修复本机历史，也不保证解除轮换阻断。

## 提交与中断恢复

1. **准备并持久化。** 写入并读回恢复日志：保留原加密恢复副本，记录目标密码保护的新 `pending`，并附上已用目标密码重新加密的历史检查点 `rekey`。原明文恢复副本先加密，避免在启用保护时持久化明文历史。
2. **发布并验证。** 发布新同步候选并读回，检查修订和冲突，更新旧格式迁移标记，清理旧 `accounts`、`state` 和本次已被取代的同步候选。清理结果需要读回验证。
3. **完成替换。** 确认没有新到达但尚未纳入事务的同步分支后，才将本机日志替换为目标密码保护的当前记录和全部历史，并移除 `pending`、`rekey`。最终日志同样需要读回验证。

准备日志中的检查点绑定本次目标记录与原日志内容，用于校验恢复所依赖的版本。它不将 Chrome Storage 变成跨设备事务，也不是对恶意本机篡改的完整防护。

提交中断时必须保留可恢复的版本，不得把失败当作“旧密码已撤销”或“密码、数据完全未变”：

- 选择原版本并提供其密码，可回滚当前账户。已有目标密码密文可能仍保留为恢复历史；之后可用当前密码与同一目标密码再次执行 `change`。
- 选择检查点对应的替换版本并提供目标密码，可继续全量重新加密与清理。成功完成前仍不能宣称旧密码失效。
- 检查点缺失、无效、同步冲突或存储仍失败时，不能静默丢弃历史或自动选择一个版本。保留副本并报告失败。

## 安全边界

- 成功保证仅针对本次纳入并验证的存储副本。已下载的加密备份仍使用导出时的密码；明文备份、其他离线设备、浏览器或系统备份不会被远程修改。
- Chrome Sync 没有跨设备 compare-and-swap（CAS）。实现会拒绝已观察到的冲突，但读回之后仍可能到达并发或离线写入，不能承诺全设备旧密码撤销。多设备应更新到支持该协议的版本，并避免同时编辑或轮换密码。
- 本机日志里的历史账户内容仍然保留，只改变其加密保护。此修复不提供安全擦除底层存储介质的保证。
- 扩展主密码保护的是存储中的 MFA 密钥，不会轮换网站或服务端的 MFA secret。若密钥或可解密副本已泄漏，必须在对应服务重新绑定 MFA，使旧密钥失效。

## 验证矩阵

测试使用合成账户与测试密码；存储故障注入使用内存存储，不接触真实账户密钥。

| 场景 | 必须检查 |
| --- | --- |
| 旧缺陷复现 | 改密后枚举所有持久化恢复密文，证明不能仅靠当前记录拒绝旧密码判断修复成功。 |
| 正常改密与连续改密 | 当前账户、每个历史版本及旧格式来源的账户内容不变；目标密码逐一可解，旧密码逐一不可解；不能只断言盐值不同。 |
| 历史使用不同盐值 | 同一旧密码但不同盐值的多个历史版本均可迁移；会话密钥不足以解密时，按每份历史自己的盐值派生。 |
| 重新启用保护 | 历史密码与目标密码一致时成功；不一致时零写入失败；先用原密码启用、再改密的路径完整覆盖。 |
| 旧、新密码混合历史 | 回滚后 `change` 可同时处理当前密码和同一目标密码的历史；第三种未知密码仍阻止任何写入。 |
| 无法解密或损坏的历史 | 返回 `recoveryPasswordRequired`，账户、同步、日志和会话写入计数均为零；原始持久化内容保持不变。结构损坏应继续由既有校验阻止写入。 |
| 每个持久化阶段失败 | 注入准备日志、同步发布、迁移标记、遗留数据清理、候选清理、最终日志写入及读回失败，确认不误报成功且副本仍可恢复。 |
| 中断后重新启动 | 用新的服务实例读取持久化状态，分别验证选择原版本回滚及选择替换版本继续；继续成功后枚举全部密文，确认旧密码不能解密。 |
| 检查点与并发 | 检查点不匹配、旧修订、晚到同步分支、存储配额错误均不丢数据、不误报完成。 |
| 语言与界面 | `securityError` 对 `Error` 和字符串错误均显示新提示；12 语言齐全，未知语言英文回退，其他错误提示不变。 |

仓库检查入口：`bun run type-check`、`bun run test:unit`、`bun run build`、`bun run test:e2e`。执行结果应单独记录，不能从本文推断。真实双设备同步、离线重连及 Chrome 配额行为仍需使用测试账号验收。
